
## Магия крови (3.3.0)

Компендиум **«Магия крови»** содержит 12 авторских заклинаний типа `spell` для D&D5e 6.0.5. Две группы: боевые заклинания и изменение тела / контроль. Доступен в разделе **Компендиумы → Багровое Причастие → Магия крови**.

Для активности `cast` в особенности NPC используйте UUID вида:

```
Compendium.bagrovoe-bleeding.blood-spells.Item.BldSpell00000001
```

ID заклинаний постоянны в рамках обновлений библиотеки. Заклинания «Багровая игла» и «Разрыв артерии» содержат флаги кровотечения для соответствующих атак. Кровотечение не срабатывает от отдельной активности спасброска без попадания. Эффекты контроля, временные хиты и бонус к КД требуют применения в обычном интерфейсе D&D5e; полная автоматизация всех заклинаний пока не заявлена. Перезарядку 5–6 «Взрыва крови» отслеживает ведущий.

Для разработчиков: `npm install --no-save classic-level@2 && node scripts/build-pack.mjs`; сборка релиза автоматически помещает каталог `packs/blood-spells` внутрь ZIP. Исходники заклинаний: `packs-src/blood-spells.json`.

## Багровый укус

1. Назначьте цель клавишей **T** до броска атаки.
2. Выполните штатную **атаку** предметом «Багровый укус».
3. После попадания модуль сам бросит спасбросок Телосложения цели, без диалога. По умолчанию Сл 11; при провале добавляется один уровень кровотечения с одним кубиком.

Используются сохранённые цели и определение попадания самой D&D5e: КД, натуральные 1/20 и полное укрытие. Работают атаки как ведущего, так и игроков. Активный ведущий должен быть подключён. Отдельная активность спасброска из версии 3.0 больше не запускает наложение эффекта; нажимать её не нужно.

Сохранённая настройка предмета `flags.bagrovoe-bleeding.inflict` имеет приоритет над названием. Пример для выбранного токена (одноразовый макрос ведущего):

```js
const item = canvas.tokens.controlled[0]?.actor.items.getName("Багровый укус");
if (item) await item.setFlag("bagrovoe-bleeding", "inflict", { levels: 1, count: 1, dc: 11 });
```

Для отключения автоматизации конкретного предмета задайте этот флаг равным `false`. Переименованные предметы с флагом продолжают работать. Реакции, изменяющие исход атаки после публикации броска, не отменяют уже выполненный спасбросок; ведущий может исправить эффект через меню токена. Старые сообщения при загрузке мира заново не обрабатываются.

## Правила кровотечения

| Уровень / число на капле | Кубик |
|---|---|
| 1 | к4 |
| 2 | к6 |
| 3 | к8 |
| 4 | к10 |
| 5 | к12 |

Число кубиков задаётся отдельно: 1–10. Например, уровень 3 и 2 кубика означают **2к8**. Тип урона — **некротический**, как в версии 3.0.

- Урон применяется в начале хода, один раз за раунд для токена в данном бою. Начало первого раунда тоже учитывается. Перемотка назад и повторный переход к уже обработанному раунду не наносят урон повторно. Дополнительный ход в том же раунде также не вызывает повторный тик.
- Сопротивления, иммунитеты, уязвимости, снижение урона, порог урона и временные хиты рассчитывает `Actor5e.applyDamage`.
- Сообщение показывает результат кубиков, урон после защит и фактическую потерю обычных и временных хитов.
- Любое фактическое увеличение обычных хитов снимает кровотечение. Получение временных хитов не снимает его.
- Отключённые эффекты не наносят урон и не показывают каплю.

## Ноль хитов и смерть

У персонажей и NPC с признаком **Important / Важный** положительный урон при уже имеющихся 0 HP добавляет **один провал спасброска от смерти**. Кровотечение не является критическим попаданием. Нулевой урон после иммунитета/защит не добавляет провал. Временные хиты поглощают урон, но не отменяют провал при 0 обычных хитов: существо всё равно получает урон.

Стабилизация снимается при положительном уроне. Если урон только снизил положительные хиты до нуля, дополнительного провала нет. Массивный урон с остатком не меньше максимума хитов вызывает мгновенную смерть. Третий провал устанавливает состояние смерти; мёртвые существа больше не получают тики.

**Обычный бросок спасброска от смерти в свой ход остаётся штатной кнопкой D&D5e.** Модуль автоматически учитывает провалы от урона, а не делает дополнительный бросок d20. Для обычных NPC поведение при 0 HP определяется настройкой автоматических состояний D&D5e.

## Управление ведущего

Щёлкните правой кнопкой по токену и нажмите **каплю** в правой колонке меню. Можно задать или прибавить уровень, изменить число кубиков и Сл Медицины, снять эффект. «Задать» с уровнем 0 тоже снимает эффект.

Для нескольких целей используйте макрос:

```js
await BagrovoeBleeding.promptApplication();
```

Назначенные цели имеют приоритет над выделенными токенами. При нескольких ведущих автоматизация и изменения выполняются у ведущего, выбранного самой Foundry как `game.users.activeGM`.

Дополнительные макросы:

```js
const token = canvas.tokens.controlled[0];
await BagrovoeBleeding.apply(token, { levels: 1, count: 2, dc: 13 }); // Добавить
await BagrovoeBleeding.set(token, { level: 2, count: 1, dc: 11 });   // Задать точно
await BagrovoeBleeding.stop(token);                              // Снять
await BagrovoeBleeding.medicine();                               // Подтвердить успех Медицины
```

API принимает Token, TokenDocument или Actor, если у актёра ровно один токен. В остальных случаях передавайте конкретный токен. `BagrovoeBleeding.get(token)` возвращает ActiveEffect. API также доступен через `game.modules.get("bagrovoe-bleeding").api`.

## Независимость токенов и обновление с 3.0

Уровень, кубики, иконка и учёт тиков привязаны к UUID конкретного токена. Несвязанные NPC, созданные из одного актёра, независимы. У связанных токенов эффекты также отдельные, но **хиты общие**, поскольку они принадлежат одному актёру. Лечение общего актёра снимает все его эффекты кровотечения.

Эффекты версии 3.0 автоматически преобразуются в отдельные эффекты имеющихся токенов. Уровни, кубики, Сл и отключённое состояние сохраняются. У актёров без токенов старый эффект сохраняется до появления токена и первого применения/тика.

## Проверки и разработка

`tests/bleeding.test.mjs` исполняет настоящие методы расчёта/применения урона и определения попадания из исходников D&D5e 6.0.5, с имитацией документов и событий Foundry. Исходники системы используются только при разработке и не входят в модуль.

```sh
git clone --depth 1 --branch release-6.0.5 https://github.com/foundryvtt/dnd5e.git ../dnd5e
node --check scripts/bleeding.js
node --test tests/bleeding.test.mjs
```

Альтернативный путь к системе: переменная окружения `DND5E_SOURCE`. GitHub Actions запускает проверки на закреплённом коммите 6.0.5. Публикация по тегу `v3.1.0` выполняется только после успешных тестов; ZIP включает манифест, скрипт, иконку и документацию.

Подробности проверки интерфейса и ограничения — в [TESTING.md](TESTING.md).
