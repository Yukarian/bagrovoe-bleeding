## Кровавая магия как способности NPC (v3.5.0)

В новом формате авторские заклинания крови можно импортировать как отдельные предметы **feat** с активностями `attack`, `save` и `utility`. В отличие от `cast`, они не вызывают штатное окно выбора ячейки заклинаний.

Чтобы автоматически оплатить способность Костями Хитов **перед** применением, задайте предмету флаг `flags.bagrovoe-bleeding.itemBloodCost`, например:
```json
{"hitDice":3,"allowHealthSubstitution":true,"healthDice":0,"healthDie":8,"requireSurvival":false}
```
Для фокусов флаг оплаты не нужен. Стоимость определяется каждым предметом отдельно, поэтому `spell.level` для предметов `feat` не требуется. Магическая характеристика ТЕЛ, Сл заклинаний обычно `8 + 2 * БМ + модификатор ТЕЛ`, но атаки по-прежнему используют обычный бонус магической атаки. Привязка эффекта кровотечения через `flags.bagrovoe-bleeding.abilities.bleed` сохраняется.

**Важно:** встроенные шаблоны NPC нужно импортировать заново. Действующие именные NPC не изменяются автоматически. Для эффектов поддержки, состояний и зон, не полностью автоматизированных системой, требуется контроль ведущего. Поведение `dnd5e.preUseActivity` после импорта требует проверки непосредственно в Foundry V14 / D&D5e 6.0.6.

## Счётчик Костей Хитов NPC (v3.4.4)

В листе NPC ведущего отображается панель «🩸 Кости Хитов» с доступным количеством, размером кости, кнопками **−** (потратить), **+** (восстановить) и **✎** (задать остаток). Максимум считывается из формулы HP NPC (например, 18d8) или system.attributes.hd.max. Потраченное количество сохраняется в `flags.bagrovoe-bleeding.hitDiceSpent`, поэтому работает независимо от видимости поля системного листа. Функции доступны через `game.modules.get("bagrovoe-bleeding").api.bloodMagic.hitDiceSummary(actor)` и `setAvailableHitDice(actor,available)`.

**Примечание:** эта панель предназначена для ведущего и NPC. Отображение после загрузки листа нужно проверить непосредственно в Foundry V14.369 и D&D5e 6.0.6. Данные старых NPC, ранее тративших КХ через system.attributes.hd.spent, читаются до первой записи нового флага.

## Кровавые заклинания и предметы, v3.4.2

Теперь обработчик `dnd5e.preUseActivity` останавливает первое использование активности, **списывает Кости Хитов или HP**, а затем повторно запускает активность без повторного списания. При 0 HP от оплаты эффекты больше не запускаются. Заклинания крови NPC не расходуют обычные ячейки. Механизм нуждается в проверке внутри реальной Foundry V14.

**Только NPC:** автоматическое кровавое колдовство работает у NPC с подтипом `заражённый` либо флагом `flags.bagrovoe-bleeding.bloodMagic = true`.

**Предметы игроков:** нужно явно задать на предмете `flags.bagrovoe-bleeding.itemBloodCost`, например `{"hitDice":2,"allowHealthSubstitution":true,"healthDice":1,"healthDie":8,"requireSurvival":false}`. При обычном использовании активности этого предмета оплата выполняется автоматически и единожды. `healthDice` добавляется к урону от недостающих костей, а не заменяет его. Предметы без такого флага не затрагиваются.

Внимание: в текущей версии выбрать конкретные Кости Хитов у мультиклассового персонажа нельзя; расходуются начиная с меньших. Урон при 0 HP ещё необходимо проверить в реальной системе смерти персонажей. Автоматическое похищение Костей Хитов предусмотрено лишь при попадании, не для зональных заклинаний. Не используйте новую механику в основном мире без предварительного теста.

## Разделение NPC и предметов игроков (3.4.1, экспериментально)

**Автоматические заклинания крови** и пассивное лечение доступны только NPC со значением `system.details.type.subtype = "заражённый"` либо флагом актора `flags.bagrovoe-bleeding.bloodMagic = true`. Одной ссылки на компендиум для игрока недостаточно, чтобы включить магию крови. Игроки не получают пассивное кровавое поглощение.

**Предметы игроков** могут отдельно использовать стоимость в Костях Хитов и/или здоровье, но для этого предмет должен получить флаг `flags.bagrovoe-bleeding.itemBloodCost`. Пример:

```json
{"hitDice":2,"allowHealthSubstitution":true,"healthDice":0,"healthDie":8,"requireSurvival":false}
```

`hitDice` — стоимость в КХ; `allowHealthSubstitution` разрешает заменять недостающие КХ здоровьем; `healthDice` — дополнительное число костей прямого урона; `healthDie` — размер этих костей; `requireSurvival` запрещает активацию, если здоровье опустится до нуля.

Макрос для выбранного предмета владельца:
```js
const actor = canvas.tokens.controlled[0]?.actor;
const item = actor?.items.getName("Название предмета");
await game.modules.get("bagrovoe-bleeding").api.bloodMagic.activateItemBloodCost(item);
```

Это **явная оплата предмета по макросу**; автоматическое применение эффектов предмета после оплаты ещё не реализовано. Действия игрока, не имеющие флага, по-прежнему не затрагиваются модулем.

**Не подтверждено:** корректность хука `dnd5e.preUseLinkedSpell` для отмены расхода обычных ячеек и возможность оплатить Кости Хитов **до** разрешения заклинания через текущий API. В текущем варианте оплата связанного заклинания совершается на `dnd5e.postUseLinkedSpell`, что не отвечает окончательному правилу для смертельного колдовства. Требуется тест в Foundry V14, прежде чем применять в реальном бою.

## Кровавое колдовство (экспериментально, 3.4.0)

Заклинания из компендиума «Магия крови» расходуют Кости Хитов в количестве, равном уровню сотворения. Фокусы бесплатны. Модуль пытается отменить расход обычных ячеек через `dnd5e.preUseLinkedSpell`; стоимость Костей Хитов учитывается через `dnd5e.postUseLinkedSpell`. **Важно:** списание происходит после успешного вызова активности, а не атомарно до разрешения заклинания. Поэтому отдельные случаи отмены и смерти до завершения каста требуют проверки в Foundry.

У NPC без классов размер и максимум Костей Хитов выводятся из формулы HP (например, 18d8); потраченные кости записываются в `system.attributes.hd.spent`. У персонажей с классами кости списываются через `system.hd.spent` классов, начиная с меньшего размера. Выбор размера кости пользователем при мультиклассе пока не реализован.

При нехватке КХ бросаются недостающие кости. Урон списывается напрямую из обычных HP, минует сопротивления, иммунитеты и временные HP. Нулевые HP могут привести к потере сознания или смерти. Правило «смерть от кровавой магии» требует отдельной проверки системы спасбросков от смерти для персонажей.

«Кровавое поглощение»: один раз в ход при попадании заклинанием крови по кровоточащей цели заклинатель восстанавливает 1к6 HP. Для магов ПО 7+ дополнительно спасбросок ТЕЛ цели против Сл заклинателя, при провале похищается одна доступная Кость Хитов и восстанавливается одна израсходованная у мага. Похищение работает у живых целей, если в Foundry доступны данные о Костях Хитов; при попаданиях, но не при уроне по области. Особое массовое жатвоприношение пока доступно через API, автоматическое применение в бою не сделано.

API: `game.modules.get("bagrovoe-bleeding").api.bloodMagic.hdPools(actor)`, `pay(actor, level)`, `regain(actor, count)`, `steal(caster, target, count, healPerDie)`.

Для тестирования: проверьте расход ячеек, уровни `cast`, мультиклассовые КХ, отрицательное здоровье, сцену с двумя ведущими и запрет похищения у нежити. Эта функциональность пока не подтверждена полноценным тестом внутри Foundry V14.

## Багровый укус

1. Назначьте цель клавишей **T** до броска атаки.
2. Выполните штатную **атаку** предметом «Багровый укус».
3. После попадания модуль сам бросит спасбросок Телосложения цели, без диалога. По умолчанию Сл 11; при провале добавляется один уровень кровотечения с одним кубиком.

Используются сохранённые цели и определение попадания самой D&D5e: КД, натуральные 1/20 и полное укрытие. Работают атаки как ведущего, так и игроков. Активный ведущий должен быть подключён. Отдельная активность спасброска из версии 3.0 больше не запускает наложение эффекта; нажимать её не нужно.

Сохранённая настройка предмета `flags.bagrovoe-bleeding.inflict` имеет приоритет над названием. Пример для выбранного токена (одноразовый макрос ведущего):

```js
const item = canvas.tokens.controlled[0]?.actor.items.getName("Багровый укус");
if (item) await item.setFlag("bagrovoe-bleeding", "inflict", { levels: 1, count: 1, dc: 11 });
```

Для отключения автоматизации конкретного предмета задайте этот флаг равным `false`. Переименованные предметы с флагом продолжают работать. Реакции, изменяющие исход атаки после публикации броска, не отменяют уже выполненный спасбросок; ведущий может исправить эффект через меню токена. Старые сообщения при загрузке мира заново не обрабатываются.

## Правила кровотечения

| Уровень / число на капле | Кубик |
|---|---|
| 1 | к4 |
| 2 | к6 |
| 3 | к8 |
| 4 | к10 |
| 5 | к12 |

Число кубиков задаётся отдельно: 1–10. Например, уровень 3 и 2 кубика означают **2к8**. Тип урона — **некротический**, как в версии 3.0.

- Урон применяется в начале хода, один раз за раунд для токена в данном бою. Начало первого раунда тоже учитывается. Перемотка назад и повторный переход к уже обработанному раунду не наносят урон повторно. Дополнительный ход в том же раунде также не вызывает повторный тик.
- Сопротивления, иммунитеты, уязвимости, снижение урона, порог урона и временные хиты рассчитывает `Actor5e.applyDamage`.
- Сообщение показывает результат кубиков, урон после защит и фактическую потерю обычных и временных хитов.
- Любое фактическое увеличение обычных хитов снимает кровотечение. Получение временных хитов не снимает его.
- Отключённые эффекты не наносят урон и не показывают каплю.

## Ноль хитов и смерть

У персонажей и NPC с признаком **Important / Важный** положительный урон при уже имеющихся 0 HP добавляет **один провал спасброска от смерти**. Кровотечение не является критическим попаданием. Нулевой урон после иммунитета/защит не добавляет провал. Временные хиты поглощают урон, но не отменяют провал при 0 обычных хитов: существо всё равно получает урон.

Стабилизация снимается при положительном уроне. Если урон только снизил положительные хиты до нуля, дополнительного провала нет. Массивный урон с остатком не меньше максимума хитов вызывает мгновенную смерть. Третий провал устанавливает состояние смерти; мёртвые существа больше не получают тики.

**Обычный бросок спасброска от смерти в свой ход остаётся штатной кнопкой D&D5e.** Модуль автоматически учитывает провалы от урона, а не делает дополнительный бросок d20. Для обычных NPC поведение при 0 HP определяется настройкой автоматических состояний D&D5e.

## Управление ведущего

Щёлкните правой кнопкой по токену и нажмите **каплю** в правой колонке меню. Можно задать или прибавить уровень, изменить число кубиков и Сл Медицины, снять эффект. «Задать» с уровнем 0 тоже снимает эффект.

Для нескольких целей используйте макрос:

```js
await BagrovoeBleeding.promptApplication();
```

Назначенные цели имеют приоритет над выделенными токенами. При нескольких ведущих автоматизация и изменения выполняются у ведущего, выбранного самой Foundry как `game.users.activeGM`.

Дополнительные макросы:

```js
const token = canvas.tokens.controlled[0];
await BagrovoeBleeding.apply(token, { levels: 1, count: 2, dc: 13 }); // Добавить
await BagrovoeBleeding.set(token, { level: 2, count: 1, dc: 11 });   // Задать точно
await BagrovoeBleeding.stop(token);                              // Снять
await BagrovoeBleeding.medicine();                               // Подтвердить успех Медицины
```

API принимает Token, TokenDocument или Actor, если у актёра ровно один токен. В остальных случаях передавайте конкретный токен. `BagrovoeBleeding.get(token)` возвращает ActiveEffect. API также доступен через `game.modules.get("bagrovoe-bleeding").api`.

## Независимость токенов и обновление с 3.0

Уровень, кубики, иконка и учёт тиков привязаны к UUID конкретного токена. Несвязанные NPC, созданные из одного актёра, независимы. У связанных токенов эффекты также отдельные, но **хиты общие**, поскольку они принадлежат одному актёру. Лечение общего актёра снимает все его эффекты кровотечения.

Эффекты версии 3.0 автоматически преобразуются в отдельные эффекты имеющихся токенов. Уровни, кубики, Сл и отключённое состояние сохраняются. У актёров без токенов старый эффект сохраняется до появления токена и первого применения/тика.

## Проверки и разработка

`tests/bleeding.test.mjs` исполняет настоящие методы расчёта/применения урона и определения попадания из исходников D&D5e 6.0.5, с имитацией документов и событий Foundry. Исходники системы используются только при разработке и не входят в модуль.

```sh
git clone --depth 1 --branch release-6.0.5 https://github.com/foundryvtt/dnd5e.git ../dnd5e
node --check scripts/bleeding.js
node --test tests/bleeding.test.mjs
```

Альтернативный путь к системе: переменная окружения `DND5E_SOURCE`. GitHub Actions запускает проверки на закреплённом коммите 6.0.5. Публикация по тегу `v3.1.0` выполняется только после успешных тестов; ZIP включает манифест, скрипт, иконку и документацию.

Подробности проверки интерфейса и ограничения — в [TESTING.md](TESTING.md).
